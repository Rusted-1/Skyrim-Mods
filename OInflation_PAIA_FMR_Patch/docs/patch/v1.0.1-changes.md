# v1.0.1 changes

No condition file changed. Only the installer text and README did, so an installed 1.0.0
works the same.

## Problem found in game
NPCs (and the player) played the P.A.I.A pregnancy idle while neither pregnant nor inflated.

Cause: P.A.I.A 4.5's own OAR submod `PAIA\Fertility Mode` (priority 91044060, installed by
P.A.I.A's "Pregnancy Mod → Fertility Mode" option):

```
IsFemale · NOT IsChild · OR(
    HasSpell Fertility Mode.esm 1B818,
    HasSpell Fertility Mode.esm 1B81A,
    NOT FactionRank("Fertility Mode 3 Fixes and Updates.esp" 862) < 33 )
```

With Fertility Mode Reloaded, `Fertility Mode 3 Fixes and Updates.esp` isn't loaded. OAR can't
resolve the faction, so `FactionRank` is false, and the `NOT` makes the OR true for every adult
female. OAR logs no warning for this.

An audit of every deployed P.A.I.A and P.A.I.A Expansion submod found no other negated condition
on a missing plugin. This patch's own submods have none either: they only negate IsChild and
IsInCombat. P.A.I.A's `OCum Inflated` submod checks `OCum.esp` MGEF `F18`, which OCum Ascended
4.1.1 doesn't have (its effects are 80A–80D, F14, F1B, F1E, F22), so it's always false.

## Fix
Reinstall P.A.I.A and pick **Pregnancy Mod: None** (and Inflation Mod: None with OCum Ascended).
This patch's *Fertility Mode Reloaded* and *OInflation* options take over both jobs. The
installer descriptions and README now say so.

Alternative without reinstalling: open OAR's editor in game (Shift+O) → PAIA → Fertility Mode
→ disable it, then save user settings.
